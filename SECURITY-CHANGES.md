# Security changes

Default changes that affect existing installations, why they were made, and what an existing install must do.
Re-render with `blcli init` and review the diff before applying anything.

## Ingress, ArgoCD and monitoring

- **Istio 1.31.3.** The default Istio version moves from 1.27.0 (end of life) to 1.31.3, the shipped args no longer say 1.20.0, and the unused `istio-operator-*` args are gone. The istio `install` now requires an istioctl at least as new as the version it installs and stops if an in-place upgrade would skip more than one minor version. Existing 1.27 installs: upgrade in place one minor version at a time (latest 1.28, 1.29 and 1.30 patch, then 1.31.3, each with the matching istioctl and `spec.tag` set in the rendered `operator.yaml`), or use revision-based canary upgrades, and restart workloads that have sidecars after each step. Istio 1.31 supports Kubernetes 1.32 to 1.37; if you use the Gateway API, install its v1.5 CRDs before 1.30. Change `istio-version: 1.20.0` in your args file to `1.31.3`, or a blcli that honours args would downgrade Istio.
- **Istio auto mTLS on.** `enableAutoMtls` is now `true`, the Istio default (it was `false`). Sidecars now use mTLS towards workloads that have a sidecar; servers stay PERMISSIVE, so clients without a sidecar keep working. No action needed, unless you rely on plaintext between sidecars (for example to inspect traffic); then set `EnableAutoMtls: false`.
- **GitOps app pods hardened.** The base Deployment and StatefulSet now render `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]` and `seccompProfile: RuntimeDefault` on the main container, and `automountServiceAccountToken: false` on the pod and its ServiceAccount; `RunAsNonRoot`/`RunAsUser` are new opt-in parameters. Only newly rendered app manifests change; before you re-render and push an existing app, set `AutomountServiceAccountToken: true` for apps that call the Kubernetes API, and make sure the app needs no Linux capabilities (for example binding a port below 1024) or setuid helpers.
- **Grafana 12.4.13 on chart 11.6.1.** The image moves from 12.3.1 to 12.4.13 (fixes CVE-2026-27880, CVE-2026-27876, CVE-2026-33378 and the other issues patched up to the 2026-10-13 security release). The chart moves from `https://grafana.github.io/helm-charts` 10.4.0 (no longer updated there) to `oci://ghcr.io/grafana-community/helm-charts` 11.6.1, which needs Kubernetes 1.25+ and helm 3.8+; `values.yaml` is refreshed to that chart's defaults. `install` now runs `helm dependency build` and checks the chart sha256 instead of `helm dependency update`, and plugins are pinned to versions. Back up the Grafana PVC before upgrading, and change `image-tag: "12.3.1"` in your args file to `12.4.13`, or a blcli that honours args would keep 12.3.1.
- **Grafana Google login limited to your domain.** `auth.google` now sets `allowed_domains` (and `hosted_domain`) from `hostedDomain`/`hosted-domain`, plus optional `allowedGroups`. Before, any Google account could sign in as Viewer and query every datasource. Set `hosted-domain` to your Google Workspace domain before upgrading (the `example.com` placeholder locks everyone out), then delete accounts from other domains under Administration > Users.
- **Grafana session cookie marked Secure.** `security.cookie_secure` is now `true`. Serve Grafana over HTTPS; users who reach it over plain HTTP can no longer keep a session.
